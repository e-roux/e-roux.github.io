## Basics

Type annotations for variables, function parameters, and return types use the `:` syntax.

[Primitives] in TypeScript include `string`, `number`, and `boolean`. Arrays can be defined using either `string[]` or the [angle-bracket syntax] `Array<number>`. [Object] type properties annotations are separated with `,` or `;`, optional specified with `?` after the property name.

```typescript
// Simple type
let isDone: boolean = false;
let decimal: number = 6;
let color: string = "blue";
let list: number[] = [1, 2, 3];

const tuple: readonly [string, number] = ["hello", 10] as const;

// Object type
interface Person {
  firstName: string;
  lastName: string;
  age?: number; // Optional property
}

// Function type
async function greet(person: Person): Promise<string> {
  return `Hello, ${person.firstName} ${person.lastName}`;
}
```

For anonymous functions, [contextual typing][contextual typing] allows TypeScript to infer types based on their usage.

```typescript
const names: Array<string> = ["Alice", "Bob", "Charlie"];
// name will be implictly typed as string
names.forEach((name) => { console.log(name.toUpperCase()); });
```

Unions are designated with `|` and [narrowing] occurs when TypeScript can deduce a more specific type for a value based on the structure of the code. 4 kind of [narrowing]:
- `typeof` type guards
- Truthiness narrowing
- `in` operator narrowing
- `instanceof` narrowing

```typescript
// Union types with narrowing
function printId(id: number | string) {
  if (typeof id === "string") {
    console.log("ID (string):", id.toUpperCase());
  } else {
    console.log("ID (number):", id);
  }
}
```

An [object] type can be defined using `type` and [cannot not be extended](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html#differences-between-type-aliases-and-interfaces) when an `interface` can.

[Type assertion]s can provide extra information that Typescript cannot know about. 

```typescript
const myCanvas = document.getElementById("main_canvas") as HTMLCanvasElement;
```

Specific strings can be referred to as [Literal].

```typescript
// Literal types
let direction: "left" | "right" = "left";
```

[`null` and `undefined`][null and undefined] are used for absent or uninitialized value. [`void`][void] represents the function return type of a function that does not return any value.

:::danger
In JavaScript, a function that doesn’t return any value will implicitly return the value undefined.
:::


## Intro to TSConfig

[TSConfig][tsconfig] is a configuration file (`tsconfig.json`) that specifies the root files and compiler options required to compile a TypeScript project. It helps customize how TypeScript compiles your code.

### Basic TSConfig Example

```json
{
  "compilerOptions": {
    "target": "es2020",
    "module": "esnext",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "forceConsistentCasingInFileNames": true,
    "outDir": "./dist"
  },
  "include": ["src/**/*"],
  "exclude": ["node_modules", "**/*.spec.ts"]
}
```

### Key TSConfig Options

- **target**: JavaScript language version for compiled files (e.g., `"es2020"`, `"esnext"`)
- **module**: Module system (`"esnext"`, `"commonjs"`, `"amd"`, etc.)
- **strict**: Enable all strict type checking options
- **outDir**: Directory for compiled JavaScript files
- **include/exclude**: Specify which files to include/exclude

### Common Configurations

- **For React Projects**:
  - Add `"jsx": "react"` or `"jsx": "react-jsx"`
  - Set `"lib": ["dom", "dom.iterable", "esnext"]`

- **For Node.js Projects**:
  - Use `"module": "commonjs"`
  - Set `"target": "es2020"` or newer
